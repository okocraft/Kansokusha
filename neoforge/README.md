# Kansokusha for NeoForge 26.2

The server mod uses the shared Kansokusha API, DuckDB storage, search parser, permission filters, and event renderer. Its data directory is `config/kansokusha` within the server instance. Set `server-key: 'okocraft:dqm'` in that directory's `config.yml` and give this server its own DuckDB file. For DQM, set `duckdb.memory-limit: '512MB'` and `duckdb.threads: 2`.

`/kansokusha search`, `/kansokusha event`, `/kansokusha inspect`, `/kansokusha teleport`, and `/kansokusha admin health` use the same search and event permission nodes as Paper. Explicit LuckPerms grants and denies take precedence over operator access. The `kansokusha.command.event.debug` permission defaults to denied for operators and must be explicitly granted to show raw data or UUID details. Chat output preserves clickable event details, pagination, and return links with their colors and hover text. Registered block, item, and entity targets use the client's translated names, including DQM content.

Saved book edits provide clickable before/after reading sections in chat. The native server book-opening packet reads the item in the player's hand, so these sections show saved pages without changing a live inventory item.

Inspection mode is session scoped and independent of free-form search permission. Left-click selects the clicked block; right-click selects an interactable block or the adjacent coordinate beyond another block. Inspection suppresses item use and block changes, checks permission again on each click, and clears on logout. Container clicks restrict results to container transactions, pickups, and transfers; double chest halves are searched together. The page links require inspection permission, while the full-history link also requires search permission.

Native capture covers the Paper catalog's block, inventory, player, entity, and world administration families through NeoForge events and small operation adapters. Backend sessions, original chat and command input, and server initiated disconnects use `neoforge_` IDs because their source boundaries differ from Paper. Give `neoforge_player_command` and `neoforge_server_command` the audit retention policy when copying a main configuration; session, chat, and disconnect IDs can use the default 30-day policy. Native payload generation 2 is JSON UTF-8; Paper payload generation 1 remains readable as its distinct binary schema. Search and detailed event views use each saved event's generation.

Player block break/place and explosion entries follow the catalog's accepted-attempt boundary after cancellation checks. Ordinary water/lava spread is recorded after each destination changes; bone meal, tree growth, portal creation, dragon egg movement, and selected mob block changes capture the exact block writes within their native operation and compare final states. A piston records each moved block at its destination and sums equal moves within one minute, flushing outstanding moves on server stop. A canceled mutation without an applied change is not submitted. Container transactions are measured within one server-side player click packet. A container change is attributed to a player when the same item and component count moves in the opposite direction in the player's inventory, cursor, or a committed toss. Page or filter changes without such a transfer are excluded. The optional Bolt `DqmMenuOrigin` interface supplies placed DQM chest coordinates when available.

The adapter captures committed vanilla hopper transfers with source/destination positions and aggregates equal routes and items for five minutes between two hoppers or fifteen seconds otherwise. It also captures vanilla hopper pickup and furnace, brewing, campfire, and crafter outputs; DQM machine internals need their own adapters. Natural changes cover crops, trees, fire spread, leaves/snow/ice fade, portal creation, dragon egg movement, fluid-formed blocks, support-loss attachments, and precipitation snow/ice formation. Weather-caused cauldron changes stay in `cauldron_level_change`. Other environmental writers may need source-specific adapters. `neoforge_kick` records a server-initiated disconnect, including timeout and policy disconnects, so it is broader than Paper's accepted kick event. The targeted mob producers cover Enderman, grazer, Ravager, Wither, Snow Golem, Silverfish and dragon block operations; modded mob writers may need adapters. The built-in catalog in `docs/v1-built-in-event-catalog.md` defines the Paper source semantics for comparison.

Build with Java 25 using `:kansokusha-neoforge:test :kansokusha-neoforge:testmodJar :kansokusha-neoforge:assemble`. `assemble` copies the GPL-3.0 product jar to the root `build/libs` distribution directory. For native verification, place the product jar and `neoforge/build/testmods/Kansokusha-NeoForge-testmod.jar` in an isolated NeoForge 26.2.0.88 server, set `-Dkansokusha.fixture.result=<writable path>`, and inspect the result and `.ui` / `.piston` companion files. The testmod is not a production dependency.
