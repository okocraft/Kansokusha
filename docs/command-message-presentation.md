# コマンドメッセージの表示設計

## コマンドの役割

- `search`: 複数の記録を比較する。相対時刻、実行主体、イベントの意味、対象、選択した重要フィールド、位置を表示する。
- `inspect`: 同じ一覧表示を使い、対象座標はヘッダーに集約する。時系列と検索へのリンクを維持する。
- `event`: 意味の要約、保存された全ペイロード、共通フィールドと技術情報の順で表示する。
- `help`: 用途、検索例、詳細への導線、inspect の操作を案内する。`version` は変更しない。

## 表示とデータの境界

`DuckDbEventSearch` は opaque なバイト列を取得する。一覧では1件16 KiBまで、詳細では全量を取得する。検索条件・権限・keyset pagination は既存の SQL に適用し、ストレージでは復号や翻訳を行わない。

共通の `EventRenderer` は行・相対時刻・リンク・技術情報を組み立てる。Paper / Velocity の presenter は自分の既知イベントと generation 1 だけを既存 Codec で復号する。Paper の各イベント群は独立した宣言的な定義を持つ。保存形式、スキーマ、公開 API は変更しない。

一覧の大きなペイロードは省略を明示する。未対応イベント・世代・破損ペイロードは共通情報へフォールバックし、他の行の表示を妨げない。外部プラグインのバイト列を組み込み形式として解釈しない。

相対時刻は送信時の `Clock` で計算し、1分未満、分、時間、日を切り捨てで選ぶ。将来は「後」、1分未満の未来は「まもなく」とする。ホバーと詳細の日時は `search-time-zone`、ミリ秒、UTC offset、zone ID を含む。再検索／ページ移動時に再計算し、送信済みのチャット行は自動更新しない。

Minecraft の名前は Paper の Material / EntityType の翻訳キーを取得し、クライアントへ TranslatableComponent として送る。未知の種類や独自名前空間は識別子を表示する。Velocity はアイテム／ブロックのレジストリを持たず、該当対象のない組み込みイベントだけを扱う。Kansokusha の文章とラベルは既存のカスタマイズ可能な日英メッセージ機構を使う。

権限確認後に presenter を呼ぶ。検索・inspect の応答時もイベント別権限を再確認する。保存された文章・コンポーネントの click / hover を調査用UIへ再利用しない。長文は一覧では100コードポイントまで、詳細では256コードポイントずつ分割して全量を表示する。アイテムは保存済みNBTを読み、詳細に本のページや複雑な属性も表示する。

## イベントごとの表示項目

以下の「詳細で確認する記録」は重点項目であり、詳細ではそれ以外の保存済みフィールドもすべて表示する。記録されていない最終状態や間接的な主体を補わない。意味と保証範囲は `v1-built-in-event-catalog.md` を正とする。

一覧には主体と時刻を共通表示する。UUID と内部 ID は主にホバー／詳細へ置く。`container_transaction` の item は数量1の同一性情報なので、移動数には `amount_delta` を使う。`item_pickup` は保存時のワールドのスタックと残数を分けて表示する。

## 検証

- 保存済みバイト列、検索上限の境界、詳細の全量取得、権限条件、既存の双方向ページネーション。
- 時刻の境界、未来、日英表示、timezone / DST、時刻ホバーと詳細クリックの両立。
- Paper 登録58種と表示定義の集合一致、Velocity 7種の既存Codecによる表示。
- 操作試行／確定差分／境界変更要求の区別、翻訳キーとフォールバック、変更前後、長文・本の全ページ。
- 未対応・破損ペイロードの分離、権限確認前に復号しないこと、応答待機中の権限失効。
- 各プラットフォームの既存コマンド・リスナー・外部 API 統合テストを GitHub Actions の `build` で実行する。
